## Test B result (2026-11-14) - watchdog reset does NOT go to TWRP
- `stage1/wdtest.S` (`boot_wdtest.img`): INFORM3=recovery, PMU WDT reset unmasked, WDT armed (WTCON 0xFF39,
  count 0xFFFF), then busy loop with SWRESET fallback. Result: the watchdog fires, but after a watchdog reset S-Boot
  ignores INFORM3 and boots BOOT again -> endless loop of the Samsung boot logo (black gaps between). No USB.
  Needs the user: Vol Up + Home + Power to TWRP. A background job then re-flashes `boot_bounce.img` and blanks the screen.
- Fix prepared, UNTESTED (run only with the user watching): `stage1/wdtest2.S` / `boot_wdtest2.img` checks
  PMU RST_STAT (0x10040404) bit 20 SYS_WDTRESET and a DRAM marker at 0x5FF00000 on entry; either one -> SWRESET to
  recovery. Every later stage (uniLoader S4) must start with the same check before anything else.
- TWRP screen: `flash_boot.sh` now blanks it (backlight 0 + fb0 blank) when the phone returns.

- User flashed a TWRP build with MTP disabled: adb comes up automatically in TWRP now.

- Facts from the selftest: boot CPU is **Cortex-A15** (MIDR 412fc0f3, MPIDR 80000000), SVC, MMU/caches off,
  load delta 0. S-Boot scans out FIMD1 window 2: 0x67000000, line 4320 B (1080 px), ARGB8888 (WINCON 0x8035).
  uniLoader reads the window from FIMD1 itself.
- Log: TWRP's /proc/last_kmsg is Android persistent_ram (ram_console) 2 MB at 0x60000000 (not sec_log):
  header {DBGC, start, size} + RS(16) header parity in the zone's last 16 bytes, same as the S4 mini.
  uniLoader writes its console there; read with `adb shell cat /proc/last_kmsg`.
- RAM to keep free for later stages: 0x46000000 (sec_log), 0x5FF00000 (marker), 0x60000000-0x601FFFFF
  (ram_console), 0x67000000-0x677E9000 (framebuffer).

## Blocked (needs the user) - resolved
- TWRP 3.1.1 on this phone exposes **MTP only** over USB (Windows: single WPD `VID_18D1&PID_4EE2`, no adb
  interface), so nothing can be done from the PC while it is in TWRP.
- TWRP sits on its "Keep System Read only?" screen and does NOT time out -> OLED burn-in risk.
- Fix: on the phone tap "Keep Read Only" (or swipe), press Power to blank the screen, and in TWRP
  **Mount -> Disable MTP** (TWRP then offers adb alone, which Windows enumerates). Then work continues.
- BOOT currently holds the bounce image: a normal boot also lands in TWRP (safe). Restore Android with
  `s4/backup/BOOT.img` if needed.
